# 게임 구조 문서

이 문서는 프로젝트 구조와 주요 기술 결정을 기록하는 살아 있는 문서다.
코드 구조, 게임 흐름, 상태 모델 또는 배포 방식이 바뀌면 같은 변경에서 이
문서도 함께 갱신한다.

## 1. 게임 개요와 기술 스택

`EchoBound`는 보이지 않는 지형과 적을 음파의 이동과 반사로 파악하는 사이드뷰
액션 플랫포머다. 현재 빌드는 이동, 점프, 구르기와 공격을 순서대로 익히는
단일 튜토리얼 스테이지다.

- 게임 엔진: Phaser 3
- 언어: TypeScript
- 개발 및 빌드: Vite
- 게임 화면: Phaser Canvas/WebGL
- HUD와 안내: HTML/CSS DOM 오버레이
- 규칙 테스트: Vitest
- 배포: GitHub Actions를 통한 GitHub Pages 정적 배포

## 2. 설계 원칙

1. 게임 규칙과 저장 가능한 상태는 Phaser 객체와 분리한다.
2. Scene은 입력 전달, 화면 구성, 카메라, 애니메이션과 이펙트를 담당한다.
3. 규칙 변경은 `src/game/simulation`의 시스템을 통해 수행한다.
4. 입력은 물리 키가 아닌 명시적인 액션으로 변환한다.
5. 지형과 적의 충돌 상태는 보이지 않는 동안에도 시뮬레이션에 존재한다.
6. 음파 충돌과 반사는 시뮬레이션에서 판정하고 Phaser는 결과만 그린다.
7. 텍스트가 많거나 반응형이어야 하는 HUD와 메뉴는 DOM으로 만든다.

├─ package.json
├─ tsconfig.json
└─ vite.config.ts

## 4. 런타임 흐름

```text
키보드 입력
  → GameScene이 InputActions와 버튼 edge로 변환
  → 1/120초 고정 스텝으로 stepSimulation 실행
  → 플레이어 이동 및 AABB 지형 충돌
  → 적 AI, 공격 지형과 전투 판정
  → 튜토리얼 구역 진행 및 주기적 환경 음원 갱신
  → 음원 이벤트 생성
  → 음파 레이 이동, 지형 반사, EchoMark 생성
  → GameViewAdapter가 플레이어·키 안내·음파·잔상을 Phaser 화면에 반영
  → SoundSynth와 DOM HUD가 GameEvent와 표시 상태를 소비
```

`GameState`가 게임 규칙의 기준이다. Phaser의 Graphics, Container, Camera와
Web Audio 노드는 폐기 가능한 화면·음향 상태이며 규칙 판정에 사용하지 않는다.

## 5. 상태와 콘텐츠 모델

정적 데이터인 `WorldDefinition`에는 월드 크기, 플레이어 시작점, AABB 지형,
적 생성 정보, 공격 지형, 주기적 환경 음원과 튜토리얼 구역 정보가 들어간다.
현재 콘텐츠는 `src/game/content/tutorialStage.ts` 하나다.

동적 `GameState`는 다음 정보를 소유한다.

- 플레이어 위치, 속도, 이동 방향, 공격 시작 방향, 체력, 접지 및 행동 타이머
- 적 위치, 속도, 순찰 범위, 체력, 행동 및 일시적 반향 표시 시간
- 공격 지형의 반향 표시 시간과 환경 음원의 다음 발생 시간
- 현재까지 도달한 튜토리얼 구역
- 진행 중인 음파와 각 레이의 위치, 방향, 남은 거리, 세기, 반사 횟수와 반사 경로 키
- 지형 면의 실제 범위로 잘린 선분 형태의 `EchoMark`
- 음향과 화면 흔들림을 요청하는 일회성 `GameEvent`
- 남은 적에 따른 세션 상태

저장 기능을 추가할 때 Phaser 객체가 아니라 이 상태 모델의 장기 데이터만
저장한다. GitHub Pages에는 서버가 없으므로 로컬 저장은 `localStorage`를
기본값으로 한다.

## 6. 이동과 전투

- 이동은 수평 가속, 중력, 최대 낙하 속도와 축 분리 AABB 충돌을 사용한다.
- 점프에는 입력 버퍼와 코요테 타임이 있다.
- 구르기는 제한 시간 동안 고정 수평 속도와 피격 무적을 제공한다.
- 공격은 준비, 활성, 회수 구간을 가지며 활성 구간에만 전방 히트박스가 켜진다.
- 공격 시작 시 입력 또는 현재 바라보는 방향을 별도로 저장한다. 공격 중 이동
  방향이 바뀌어도 진행 중인 공격 히트박스의 방향은 바뀌지 않는다.
- 지상 구르기 중 점프 입력은 구르기를 취소하고 즉시 점프로 전환한다.
- 공격 중 구르기 입력은 공격과 기존 명중 기록을 취소하고 구르기로 전환한다.
- 플레이어가 사망하면 현재 위치에서 모든 이동 속도를 즉시 0으로 고정한다.
- 공명 분쇄기는 항상 피해 판정을 가지며 구르기의 무적 시간에만 안전하게
  통과할 수 있다. 구르기 이외의 행동으로 접촉하면 피해 무적 여부와 관계없이
  진입한 쪽 바깥으로 밀려나므로 체력으로 버티며 우회할 수 없다. 현재 공격
  범위의 높이는 160px이다.
- 점프 수로의 오른쪽 언덕 윗면은 공중 플랫폼과 같은 y=550에 있으며, 구덩이에
  떨어진 플레이어는 높이가 다른 복귀 발판을 밟아 다시 올라올 수 있다.
- 적은 지정된 구간을 순찰하고 가까운 플레이어를 향해 예고 음파 후 공격한다.
- 적을 모두 처치하면 완료, 체력이 0이 되거나 낙사하면 실패 상태가 된다.

## 7. 음파와 가시성

음파는 원형 텍스처 확대가 아니라 방사형 레이로 계산한다. 처음에는 24개
레이로 시작하고, 인접한 파면 판정점의 간격이 20px보다 커지면 그 사이에 새
레이를 삽입한다. 각 레이는 고정 스텝마다 이동하며 가장 가까운 지형 AABB
표면에서 법선을 얻어 반사한다.

- 총 반사 횟수에는 제한이 없다.
- 충돌할 때마다 이미 이동한 거리를 차감한 뒤 남은 거리를 64%로 줄인다.
- 시각적 세기도 충돌할 때마다 70%로 감쇠한다.
- 남은 이동 거리가 30px 미만이면 레이를 제거한다.
- 반사 횟수는 디버깅과 표현에만 사용하며 종료 조건으로 사용하지 않는다.
- 모든 음원은 이전 최대 이동 거리의 50%만 이동하도록 각 음원 발생 지점의
  거리 값을 개별 조정한다. 전파 속도와 충돌 후 감쇠율은 유지한다.
- 레이는 충돌한 지형 면과 법선으로 만든 반사 경로 키를 기록한다. 동일한
  반사 경로의 인접 판정점만 이어 잘못된 지형 관통선을 만들지 않는다.
- 파면 판정점 자체는 그리지 않고 인접 판정점을 연결한 연속 선만 표시한다.
- 지형 충돌 지점은 해당 AABB 면의 시작과 끝을 넘지 않도록 잘린 선분 잔상으로
  약 0.68초 표시한다.
- 음파가 적의 AABB를 지나가거나 적 자신이 소리를 내면 적 외곽선을 잠시 표시한다.

플레이어는 현재 실제 충돌 크기의 직사각형 히트박스로 항상 보인다. 적은
디버그 모드가 아니면 기본적으로 보이지 않으며, 음파에 드러날 때 실제 충돌
히트박스만 표시한다. 플레이어와 적의 공격도 규칙 판정에 사용하는 동일한
직사각형 범위를 표시하며 캐릭터 장식 도형이나 공격 궤적은 그리지 않는다.
실제 음향은 Web Audio로 임시 합성하며 좌우 위치에 따라 패닝한다. 시각
정보만으로도 플레이할 수 있다.

음원 발생 조건은 플레이어 발걸음과 착지, 공격의 지형·적 명중, 적 발걸음과
공격, 피격 및 사망이다. 튜토리얼의 물방울과 쇠사슬은 진행 방향을 알려주는
청록색 환경 음파를, 공명 분쇄기는 자신의 공격 범위를 드러내는 붉은 음파를
주기적으로 방출한다. `P` 강제 펄스와 `F3` 충돌체 표시는 개발 도구다.

## 8. Scene, 카메라와 UI

- `BootScene`: 초기화 후 게임 Scene으로 전환한다.
- `GameScene`: 입력 edge를 보존해 고정 스텝에 전달하고 화면과 이벤트를 연결한다.
- `GameViewAdapter`: 플레이어·적·공격 히트박스, 플레이어 상단의 현재 조작 키,
  음파와 지형 반향을 동기화한다.
- 카메라: 플레이어 추적형이며 진행 방향에 약간의 선행 시야를 둔다.
- DOM HUD: 체력, 남은 적과 완료·실패 결과를 표시한다. 튜토리얼 진행 중에는
  긴 설명 대신 현재 필요한 키만 플레이어 히트박스 위에 39px로 표시한다.

## 9. 에셋 정책

현재 프로토타입은 플레이 감각을 빠르게 검증하기 위해 Phaser 도형과 Web Audio
합성음을 사용한다. 외부 에셋을 추가할 때는 다음 규칙을 적용한다.

- 정적 파일은 `public/assets` 아래에 도메인별로 저장한다.
- 게임 코드에서는 `src/game/assets/manifest.ts`의 안정적인 키를 사용한다.
- 원본 에셋과 라이선스 또는 출처 정보도 저장소에 포함한다.
- 대용량 에셋을 추가하기 전에 압축과 브라우저 로딩 비용을 검토한다.

## 10. 검증과 배포

- `npm test`: AABB 레이 판정, 이동, 점프, 구르기, 전투, 적 반향 및 거리 감쇠
  기반 연속 반사를 검증한다.
- `npm run build`: TypeScript 검사와 Vite 프로덕션 빌드를 수행한다.
- 브라우저 플레이테스트: 첫 화면, 주요 입력, 음파 표현, HUD와 런타임 오류를
  스크린샷으로 확인한다.

`main` 브랜치에 푸시하면 `.github/workflows/deploy.yml`이 의존성 설치, 빌드,
Pages 아티팩트 업로드와 배포를 수행한다. Vite의 `base`는 상대 경로다.
