# 게임 구조 문서

이 문서는 프로젝트 구조와 주요 기술 결정을 기록하는 살아 있는 문서다.
코드 구조, 게임 흐름, 상태 모델 또는 배포 방식이 바뀌면 같은 변경에서 이
문서도 함께 갱신한다.

## 1. 게임 개요와 기술 스택

`EchoBound`는 보이지 않는 지형과 적을 음파의 이동과 반사로 파악하는 사이드뷰
액션 플랫포머다. 현재 빌드는 이동, 점프, 구르기와 공격을 순서대로 익히는
튜토리얼, 버튼 기반 탈출 기믹을 가진 1스테이지와 2스테이지 임시 진입실을
출구로 연결한다.

- 게임 엔진: Phaser 3
- 언어: TypeScript
- 개발 및 빌드: Vite
- 게임 화면: Phaser Canvas/WebGL
- HUD와 안내: HTML/CSS DOM 오버레이
- 규칙 테스트: Vitest
- 배포: GitHub Actions를 통한 GitHub Pages 정적 배포

## 2. 설계 원칙

1. 게임 규칙과 저장 가능한 상태는 Phaser 객체와 분리한다.
2. Scene은 입력 전달, 화면 구성, 카메라, 애니메이션과 이펙트를 담당한다.
3. 규칙 변경은 `src/game/simulation`의 시스템을 통해 수행한다.
4. 입력은 물리 키가 아닌 명시적인 액션으로 변환한다.
5. 지형과 적의 충돌 상태는 보이지 않는 동안에도 시뮬레이션에 존재한다.
6. 음파 충돌과 반사는 시뮬레이션에서 판정하고 Phaser는 결과만 그린다.
7. 텍스트가 많거나 반응형이어야 하는 HUD와 메뉴는 DOM으로 만든다.

```text
│  ├─ game/
│  │  ├─ assets/            # 에셋 매니페스트와 키
│  │  ├─ content/           # 공유 스테이지 스키마, 레지스트리와 정적 맵 정의
│  │  ├─ input/             # 물리 키와 분리된 InputActions
│  │  ├─ progression/       # 맵 전환 체크포인트와 직렬화
│  │  └─ simulation/
│  │     ├─ collision/      # AABB 이동 충돌과 레이 교차 판정
│  │     ├─ rules/          # 플레이어, 적, 음파 튜닝 값
│  │     ├─ state.ts        # 직렬화 가능한 동적 게임 상태
│  │     └─ systems/        # 이동, 전투, AI, 음파, 통합 스텝
│  ├─ phaser/
│  │  ├─ scenes/            # Scene 생명주기와 입력 연결
│  │  └─ view/              # 상태 동기화, 도형 렌더링, 임시 음향
│  ├─ ui/                   # DOM 기반 HUD와 안내
│  └─ main.ts               # 애플리케이션 진입점
├─ tests/                   # 순수 시뮬레이션 테스트
├─ index.html
├─ editor.html              # 외부 맵 에디터 진입점
├─ package.json
├─ tsconfig.json
└─ vite.config.ts
```

## 4. 런타임 흐름

```text
키보드 입력
  → GameScene이 InputActions와 버튼 edge로 변환
  → 1/120초 고정 스텝으로 stepSimulation 실행
  → 플레이어 이동 및 AABB 지형 충돌
  → 활성 문 지형을 계산해 적 AI, 공격 지형과 전투 판정
  → 버튼 상태에 따라 두 문, 성장 장해물과 추적 적 갱신
  → 튜토리얼 구역 진행 및 주기적 환경 음원 갱신
  → 음원 이벤트 생성
  → 음파 레이 이동, 지형 반사, EchoMark 생성
  → 출구 접촉 시 현재 처치 진행도를 체크포인트로 만들고 대상 StageDefinition 로드
  → 죽음 모션 뒤 또는 R 입력 시 최근 체크포인트의 맵·진행도·위치 복원
  → GameViewAdapter가 플레이어 스프라이트·키 안내·음파·잔상을 Phaser 화면에 반영
  → SoundSynth와 DOM HUD가 GameEvent와 표시 상태를 소비
```

`GameState`가 게임 규칙의 기준이다. Phaser의 Graphics, Container, Camera와
Web Audio 노드는 폐기 가능한 화면·음향 상태이며 규칙 판정에 사용하지 않는다.

## 5. 상태와 콘텐츠 모델

정적 데이터인 `WorldDefinition`에는 월드 크기, 플레이어 시작점, AABB 지형,
적 생성 정보, 공격 지형, 주기적 환경 음원과 튜토리얼 구역 정보가 들어간다.
`StageDefinition`은 여기에 안정적인 스테이지 ID, 스키마 버전, 복수 도착점과
다른 스테이지를 가리키는 출구를 더한다. `stages.ts`가 튜토리얼, 1스테이지와
2스테이지 임시 진입실을 ID로 조회하는 레지스트리다. 지형·장해물·적의 선택적 `kind` 문자열은 이후 새
타입을 에디터와 런타임에 추가할 때 저장 형식을 깨지 않고 분기하는 확장점이다.

동적 `GameState`는 다음 정보를 소유한다.

- 플레이어 위치, 속도, 이동 방향, 공격 시작 방향, 일시적인 수평 히트박스
  오프셋, 지상 공격 순번, 공격 시작 시 공중 여부, 체력, 접지, 공중 최고점 및
  행동 타이머
- 적 위치, 속도, 이동 방향, 공격 시작 방향, 순찰 범위, 체력, 행동, 위험 지형
  피해 대기 시간, 사망 후 경과 시간 및 일시적 반향 표시 시간. 사망 적도 시체
  상태로 배열에 계속 남는다. 특수 적은 종류, 활성 여부와 다음 주기 음파 시간도
  가진다.
- 지형별 활성·버튼 눌림·반향 상태. 문 충돌과 음파 반사는 활성 지형만 사용한다.
- 공격 지형의 현재 AABB, 성장 활성·경과 시간, 반향 표시 시간, 피해 반응
  모션 시간·접촉 방향·높이와 환경 음원의 다음 발생 시간
- 현재까지 도달한 튜토리얼 구역
- 진행 중인 음파와 각 레이의 위치, 방향, 남은 거리, 세기, 반사 횟수와 반사 경로 키
- 지형 면의 실제 범위로 잘린 선분 형태의 `EchoMark`
- 음향과 화면 흔들림을 요청하는 일회성 `GameEvent`
- 남은 적에 따른 세션 상태

`CheckpointSave`는 현재 스테이지와 대상 도착 위치·방향, 방문/완료한 스테이지,
스테이지별 일반 적과 보스 처치 ID를 저장한다. 출구로 맵이 바뀌는 순간에만
새 체크포인트를 만들고 `localStorage`의 `echobound.checkpoint.v1`에 기록한다.
죽음 모션이 끝나거나 `R`을 누르면 최근 체크포인트에서 순수 `GameState`를 다시
만들며, 체크포인트 이후에 일어난 처치와 이동은 되돌아간다. 저장소 접근이
차단되어도 같은 실행 세션의 메모리 체크포인트는 유지한다. Phaser 객체와 음파,
일회성 이벤트 같은 화면·순간 상태는 저장하지 않는다.

### 외부 맵 에디터

`editor.html`은 게임 Scene에 포함되지 않는 독립 실행형 단일 파일이면서 Vite의
두 번째 빌드 진입점이다. 외부 모듈, 스타일시트, 에셋과 서버 요청이 없으므로
탐색기에서 더블클릭해 `file://`로 열어도 동작한다. Canvas는 맵의 격자와 배치
결과를 그리고, DOM 도구/검사기/내보내기 영역은 다음 항목을 편집한다.

- 충돌 지형과 피해 장해물의 사각 범위
- 일반 적/보스의 위치, 순찰 범위, 체력과 `kind`
- 맵 전환 도착점과 출구의 대상 스테이지/도착점
- 스테이지 ID, 이름과 월드 크기

런타임의 1스테이지는 `map/stage-1.json`을 직접 가져와 맵 파일을 단일 원본으로
사용한다. 단일 파일 실행을 위해 에디터 안에는 같은 초기 1스테이지 JSON, CSS와 일반 JavaScript
검증/편집 로직을 인라인으로 둔다. 데이터 형식은 게임의 `StageDefinition`과
동일하며 자동화 테스트가 내장 초기 맵과 `stageOne.ts`의 일치를 확인한다. JSON은
에디터에 다시 불러올 수 있고 TypeScript 출력은 콘텐츠 파일에 그대로 넣은 뒤
`stages.ts`에 등록한다. 새 배치 계열은 `editor.html`의 도구 카탈로그와 공유
스키마 변환을 함께 확장한다. 기존 계열의 새 모양은 항목의 `kind` 값과 런타임
처리만 추가하면 된다. 선택 도구는 지형, 장해물, 적, 도착점과 출구를 격자
단위로 드래그 이동하며, 일반 적을 이동할 때는 순찰 범위도 같은 수평 거리만큼
함께 옮긴다. 선택 항목은 도구 레일의 삭제 버튼이나 `Delete`/`Backspace` 키로
제거한다. `bounds`를 가진 지형, 장해물과 출구를 선택하면 네 모서리에 크기 조절
핸들이 나타난다. 핸들을 끌면 반대쪽 모서리는 고정되고 선택한 격자 단위로
크기가 바뀌며, 음수 크기를 막기 위해 최소 크기는 한 격자로 제한한다. 적과
도착점은 저장 스키마에 크기가 없는 점 객체이므로 크기 조절 대상에서 제외한다.

에디터는 런타임과 같은 960×540 뷰포트 크기를 사용해 맵 하단 기준의 고정된
카메라 상단선을 점선으로 표시한다. 선 아래의 반투명 영역이 실제 게임에 보이는
세로 범위다. 단일 파일 실행을 유지하기 위해 뷰포트 수치는 에디터에 인라인으로
복제하되, 자동화 테스트가 `src/phaser/viewport.ts`의 런타임 수치와 일치하는지
검증한다.

## 6. 이동과 전투

- 이동은 수평 가속, 중력, 최대 낙하 속도와 축 분리 AABB 충돌을 사용한다.
- 플레이어의 실제 충돌·피격 히트박스는 32×84px 정수 크기다. 3배 표시
  스프라이트보다 폭을 좁게 유지해 캐릭터 몸통 중심에 맞추며, 지형·적 공격·위험
  지형 판정에 사용한다. 판정용 히트박스는 화면에 표시하지 않는다.
- 수평 이동, 구르기 또는 공격 중에는 실제 충돌·피격 히트박스를 행동 방향으로
  20px 옮기고 행동과 이동이 끝나면 스프라이트 중심으로 되돌린다. 공격하면서
  반대 방향으로 이동할 때는 시작 시 저장한 공격 방향을 우선한다. 공격 판정
  자체는 스프라이트 위치와 `attackFacing`을 기준으로 기존 범위를 유지한다.
- 월드의 공간 좌표와 이동 수치는 초기 1배 좌표계의 2배를 사용한다. 960×540
  뷰포트는 유지하므로 플레이어, 적과 지형이 기존보다 두 배 크게 보이며, 이동과
  점프에 걸리는 시간 비율은 유지된다.
- 공중에서는 가장 작은 y 좌표를 최고점으로 기록한다. 착지 시 `착지 y - 공중
  최고점 y`로 낙하 높이를 구하고 착지 음파의 최대 이동 거리와 세기를 선형으로
  키운다. 최대 이동 거리는 180px에서 시작해 낙하 1px당 1px 증가하며 840px로
  제한한다. 좌표계 확대 전과 같은 낙하 비율에서 같은 세기가 되도록 1px당 세기
  증가량은 절반으로 조정한다.
- 점프에는 입력 버퍼와 코요테 타임이 있다.
- 구르기는 제한 시간 동안 고정 수평 속도와 피격 무적을 제공한다.
- 공격은 준비, 활성, 회수 구간을 가지며 활성 구간에만 전방 히트박스가 켜진다.
  지상 공격 판정은 116×120px, 공중 공격 판정은 중심을 8px 위로 올린
  116×140px다. 너비는 이전 128px의 90%에 가장 가까우면서 중심 계산에서
  소수 픽셀이 생기지 않는 짝수 값으로 조정했다.
- 공격 시작 시 입력 또는 현재 바라보는 방향을 별도로 저장한다. 공격 중 이동
  방향이 바뀌어도 진행 중인 공격 히트박스의 방향은 바뀌지 않는다.
- 지상 구르기 중 점프 입력은 구르기를 취소하고 즉시 점프로 전환한다.
- 공격 중 구르기 입력은 공격과 기존 명중 기록을 취소하고 구르기로 전환한다.
- 구르기 중 공격 입력은 구르기와 구르기 무적을 취소하고 즉시 공격으로
  전환한다. 구르기 무적은 별도 타이머가 아니라 `roll` 행동 자체로 판정하므로
  공격 전환 뒤에는 남지 않는다.
- 플레이어가 피해를 받으면 진행 중인 일반 행동이나 공격을 피격 또는 사망으로
  전환하고 공격 명중 기록을 비운다. 구르기는 무적이므로 정상 지속된다.
- 접지 또는 코요테 타임 안에서 공격 중 점프하면 공격과 기존 명중 기록을
  취소하고 즉시 점프한다. 피격 중에는 점프, 공격과 구르기를 새로 시작할 수 없다.
- 뷰는 행동 상태가 바뀌는 즉시 대응 애니메이션으로 전환한다. 공격→구르기는
  공격 시트에서 DASH로, 구르기→공격은 DASH에서 공격 시트로, 공격→점프는
  공격 시트에서 JUMP-START로 즉시 바뀐다. 공격→피격은 HURT로 전환한다.
- 지상 공격을 시작할 때 `ATTACK 1`, `ATTACK 2`, `ATTACK 3` 순번을 상태에
  기록하고 세 번째 다음에는 첫 번째로 순환한다. 공중에서 시작한 공격은 순번을
  소비하지 않고 `AIR ATTACK`을 사용한다.
- 플레이어가 사망하면 현재 위치에서 모든 이동 속도를 즉시 0으로 고정한다.
- 공명 분쇄기는 항상 피해 판정을 가지며 구르기의 무적 시간에만 안전하게
  통과할 수 있다. 구르기 이외의 행동으로 접촉하면 피해 무적 여부와 관계없이
  진입한 쪽 바깥으로 밀려나므로 체력으로 버티며 우회할 수 없다. 현재 공격
  범위의 높이는 320px이다.
- 플레이어가 공명 분쇄기에 접촉해 실제로 체력이 감소하면 본체 형상은 유지한 채
  접촉한 높이와 방향에서 플레이어 쪽으로 3×3px 셀 기반의 붉은 번개가 0.32초
  동안 충격·분산·소멸 순서로 나타난다. 주기 음파, 피해 무적 중 접촉과 구르기
  통과에는 재생하지 않으며 기존 피해 판정 범위를 확장하지 않는다.
- 점프 구간의 기본 바닥은 오른쪽 언덕 시작점까지 이어지며, 공중 플랫폼 아래의
  최하단 바닥과 구덩이는 없다. 오른쪽 가장자리의 높은 발판은 유지한다.
- 적은 지정된 구간을 순찰한다. 플레이어를 감지하면 작은 붉은 예고 음파를
  최대 세기로 내보내고 정지한 뒤 0.4초 후 감지 방향으로 공격한다. 감지 순간의
  방향을 별도 저장하므로 예고와 공격 도중 이동 방향이 바뀌어도 공격 범위와
  넉백 방향은 바뀌지 않는다. 공격 시도 범위는 가로 136px, 세로 86px로 실제
  공격 박스보다 약간 안쪽이며, 정지한 플레이어를 향한 헛공격을 방지한다.
- 적이 공격하는 동안 공격 박스와 플레이어가 겹치면 즉시 피해를 시도한다.
  구르기와 피격 후 무적 시간이 남아 있으면 피해를 받지 않으며, 무적이 끝난 뒤
  공격 박스와 계속 겹쳐 있으면 바로 피해를 받는다.
- 적 공격 실루엣은 경계 자세에서 짧게 접힌 낫팔을 유지하다 공격 시작과 동시에
  전방 124px 판정 끝을 덮는 3px 셀까지 길게 뻗는다. 이후 후려치기와 회수
  프레임에서 팔 길이를 단계적으로 줄여 몸 안쪽으로 되돌린다.
- 적도 플레이어에게 피해를 주는 공격 지형과 겹치면 피해를 받는다. 같은 지형에
  계속 닿아 있을 때는 적 전용 0.8초 피해 대기 시간을 적용한다.
- 적은 사망 시 반동·낙하·붕괴 모션을 거쳐 바닥에 시체로 정착한다. 시체는 적
  상태에서 제거되지 않으며 바닥 정착 이동을 제외한 충돌, 공격과 피해 판정에는
  참여하지 않는다.
- 적을 모두 처치하면 완료, 체력이 0이 되거나 낙사하면 실패 상태가 된다.

## 7. 음파와 가시성

음파는 원형 텍스처 확대가 아니라 방사형 레이로 계산한다. 처음에는 24개
레이로 시작하고, 인접한 파면 판정점의 간격이 40px보다 커지면 그 사이에 새
레이를 삽입한다. 각 레이는 고정 스텝마다 이동하며 가장 가까운 지형 AABB
표면에서 법선을 얻어 반사한다.

- 총 반사 횟수에는 제한이 없다.
- 충돌할 때마다 이미 이동한 거리를 차감한 뒤 남은 거리를 64%로 줄인다.
- 시각적 세기도 충돌할 때마다 70%로 감쇠한다.
- 남은 이동 거리가 60px 미만이면 레이를 제거한다.
- 반사 횟수는 디버깅과 표현에만 사용하며 종료 조건으로 사용하지 않는다.
- 모든 음원은 이전 최대 이동 거리의 50%만 이동하도록 각 음원 발생 지점의
  거리 값을 개별 조정한다. 전파 속도와 충돌 후 감쇠율은 유지한다.
- 레이는 충돌한 지형 면과 법선으로 만든 반사 경로 키를 기록한다. 동일한
  반사 경로의 인접 판정점만 이어 잘못된 지형 관통선을 만들지 않는다.
- 파면 판정점 자체는 그리지 않고 인접 판정점 사이를 3×3px 정사각형 셀로
  래스터화해 두 칸(6px) 두께의 픽셀 파면으로 표시한다.
- 적의 공격 전 붉은 경고 음파는 3×3px 셀 두 칸 두께인 다른 음파와 달리
  네 칸(12px) 두께로 표시해 즉시 구분할 수 있게 한다.
- 지형 충돌 지점은 해당 AABB 면의 시작과 끝을 넘지 않도록 잘린 선분 잔상으로
  약 0.68초 표시하며, 음파와 동일하게 3×3px 정사각형 셀 두 칸 두께로
  래스터화한다.
  선분 바로 바깥을 다른 지형이 차지하는 구간은 제거해 구덩이와 맞닿은
  모서리에서 가려진 면의 흔적이 드러나지 않게 한다.
- 음파가 살아 있는 적의 AABB 또는 바닥에 누운 시체 전용 반향 범위를 지나가거나
  적 자신이 소리를 내면 해당 실루엣을 잠시 표시한다. 시체는 반향 시간이 끝나면
  보이지 않지만 상태에서 제거되지 않으므로 이후 음파가 오면 다시 드러난다.
- 플레이어가 만든 음파가 적에게 처음 닿으면 현재 레이의 수평 입사 방향만
  사용해 음파가 온 좌우 방향으로 적의 이동 방향을 바꾼다. 반사된 음파도 실제
  입사 방향을 사용하며, 같은 음파에는 적 하나당 한 번만 반응한다.
- 1스테이지의 수면 적은 정지한 채 2.2초마다 음파를 내고 장해물 피해를 받지
  않는다. 비행 적은 중력 없이 지정 구간을 왕복하며 플레이어 음파가 들어온
  좌우 방향으로 선회한다.
- 버튼이 눌리면 수면 중인 추적 적이 깨어난다. 추적 적은 플레이어를 향해
  700px/s²로 가속하되 560px/s에서 속도를 제한해 급격한 방향 전환을 피하고,
  1.15초마다 음파를 낸다. 이 튜닝은 버튼에서 왼쪽으로 달리는 플레이어와
  x=900 부근에서 조우하도록 정했다.
- 고정 즉사 장해물은 별도 음파를 만들지 않으며 구르기 중에도 플레이어를 즉사시킨다.
  성장 장해물은 주기적인 붉은 음파를 내고, 버튼 이후 오른쪽 끝을 고정한 채
  왼쪽으로 확장한다. 성장 속도는 0~2초에 걷기 속도의 50%, 2~10초에 100%,
  이후 120%다.

플레이어는 캐릭터 스프라이트만 보이며 실제 충돌·피격 히트박스와 공격 히트박스는
표시하지 않는다. 적은 기본적으로 보이지 않으며 음파에 드러날 때 3×3px 셀로
완전히 채운 붉은 측면 실루엣을 표시한다. 낮은 포식자 체형, 뒤로 흐르는 꼬리,
등 가시, 전방 주둥이와 낫 앞발의 외곽만 사용하고 눈·갈비뼈 같은 내부 표현은
그리지 않는다. 순찰 중에는 네 프레임 보행, 경계 중에는 두 프레임 준비 자세,
공격 중에는 돌진·후려치기·회수 자세를 상태 시간에 맞춰 선택한다. 경계 사각형은
그리지 않고 계속 시뮬레이션 판정에만 사용한다. 공명 분쇄기도 내부 무늬 없이
톱니 외곽 전체를 같은 붉은색으로 채운 첨탑 실루엣으로 표현한다. 적의 공격
히트박스는 표시하지 않는다. 1스테이지 수면 적과 날개 달린 비행 적은 종류별
실루엣을 사용하며, 버튼은 음파로 드러날 때만 전체를 주황색으로 채운다.
실제 음향은 Web Audio로 임시 합성하며 좌우 위치에 따라 패닝한다. 시각
정보만으로도 플레이할 수 있다.

음원 발생 조건은 플레이어 발걸음과 착지, 공격의 적 명중, 적 발걸음과 공격,
피격 및 사망이다. 플레이어 공격이 지형에 명중하면 화면 충격만 발생하고 음파는
생성하지 않는다. 튜토리얼의 물방울과 쇠사슬은 진행 방향을 알려주는
청록색 환경 음파를, 공명 분쇄기는 자신의 공격 범위를 드러내는 붉은 음파를
주기적으로 방출한다. 적 발걸음 파장은 플레이어 발걸음과 같은 파란색을 사용해
발소리라는 공통 의미를 유지한다. `R`은 가장 최근 맵 전환 체크포인트로
되돌리지만 화면에는 별도 안내를 표시하지 않는다.

착지 음파는 착지 직전 속도가 아니라 실제 낙하 높이를 사용한다. 같은 속도로
착지하더라도 더 높은 곳에서 떨어졌다면 더 넓고 강한 음파가 생성된다.

## 8. Scene, 카메라와 UI

- `BootScene`: 플레이어 스프라이트 시트를 로드하고 애니메이션을 등록한 뒤 게임
  Scene으로 전환한다.
- `GameScene`: 입력 edge를 보존해 고정 스텝에 전달하고, 스테이지 출구와
  체크포인트 저장/복원, 현재 스테이지에 맞는 화면 재구성과 이벤트를 연결한다.
- `GameViewAdapter`: 시뮬레이션 상태로 플레이어 애니메이션과 방향을 선택하고,
  음파로 드러난 적·공명 분쇄기·성장 장해물의 3×3px 위협 실루엣, 주황색 버튼, 플레이어 상단의 현재
  조작 키, 음파와 지형 반향을 동기화한다. 플레이어와 양측 공격의 판정 범위는
  렌더링하지 않는다.
- 카메라: 플레이어의 수평 위치만 추적하며, 수직 위치는 월드 하단 기준으로
  고정한다. 2배 좌표계에 맞춘 수평 데드존과 진행 방향 선행 시야를 사용하고,
  화면 충격도 수평으로만 적용한다. 정수 배율 스프라이트가 이동 중 흐려지지
  않도록 렌더 좌표를 픽셀에 맞춘다.
- DOM HUD: 좌측 상단에 현재 체력에 따라 채워지는 27×27px 정사각형 4개를
  9px 간격으로 배치한다. 브랜드, 남은 적, 완료·실패 결과와 개발 도구 문구는
  표시하지 않는다. 튜토리얼 진행 중에는 현재 필요한
  키만 플레이어 히트박스 위에 외부 폰트 없는 5×7 비트맵 글리프로 표시하며,
  공격의 `J` 안내가 끝난 뒤 종합 시험 구역에서는 조작 안내를 표시하지 않는다.

## 9. 에셋 정책

플레이어는 `public/assets/characters/player`의 96px 고정 프레임 스프라이트 시트를
원본의 3배 정수 배율로 표시한다. 대기, 달리기, DASH, 점프 시작·상승·정점
전환·낙하, 지상 공격 3종,
공중 공격, 피격과 사망 애니메이션을 시뮬레이션 상태에서 선택한다. 점프 단계는
수직 속도에 따라 `JUMP-START`→`JUMP`→`JUMP-TRANSITION`→`JUMP-FALL`로
전환한다. 공격 방향은 진행 중인 판정과 일치하도록 `attackFacing`을 따른다. 적과
환경은 Phaser 도형을, 음향은 Web Audio 합성음을 사용한다. 외부 에셋을 추가할
때는 다음 규칙을 적용한다.

- 정적 파일은 `public/assets` 아래에 도메인별로 저장한다.
- 게임 코드에서는 `src/game/assets/manifest.ts`의 안정적인 키를 사용한다.
- 원본 에셋과 라이선스 또는 출처 정보도 저장소에 포함한다.
- 대용량 에셋을 추가하기 전에 압축과 브라우저 로딩 비용을 검토한다.

## 10. 검증과 배포

- `npm test`: AABB 레이 판정, 이동, 점프, 구르기, 낙하 높이별 착지 음파,
  전투, 적 반향 및 거리 감쇠 기반 연속 반사를 검증한다.
- `npm run build`: TypeScript 검사와 Vite 프로덕션 빌드를 수행한다.
- 저장/전환과 스테이지 스키마는 Vitest로, TypeScript 및 두 HTML 진입점은
  `npm run build`로 검증한다. 저장소 지침에 따라 브라우저 자동화와 스크린샷
  플레이테스트는 수행하지 않는다.

`main` 브랜치에 푸시하면 `.github/workflows/deploy.yml`이 의존성 설치, 빌드,
Pages 아티팩트 업로드와 배포를 수행한다. Vite의 `base`는 상대 경로다.
